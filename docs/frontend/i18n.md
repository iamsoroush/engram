# Internationalization (fa/en + RTL)

Engram ships bilingual: Persian (fa, default, RTL) and English (en, LTR). This doc is the product-truth
record of how language works across surfaces and what is in vs out of scope.

## The two axes — chrome vs. content

Language is **two independent axes**. Conflating them is the most common i18n bug here.

- **Chrome (UI language).** Buttons, labels, nav, toasts, dialogs, empty/error states. Follows the
  **app/UI language** and is the only thing routed through the `shared/i18n` `t()` seam. Never hardcode
  chrome strings — the dev guard (`npm run i18n:guard`) ratchets against new literals.
- **Clinical content.** Report prose, image captions, treatment/dose text, dictated aftercare, patient
  share copy. Follows **`reportLanguage` / `shareLanguage`** (the clinician's or patient's chosen output
  language) and is produced by the AI engine — it is **never** translated by `t()`. Carry it in
  `data-content` so the guard and any chrome scan skip it.

Rule of thumb: if a human typed/dictated it or the AI generated it, it's content; if the app authored it,
it's chrome.

## Surfaces and their language authority

| Surface | Authority | Source of language | `<html dir/lang>` writer |
| --- | --- | --- | --- |
| Public (landing/login/sign-up/onboarding) | public seam (`useUiLang`) | `localStorage` (`engram-ui-lang`), default fa | `useUiLang` |
| Authenticated aesthetics app | `AppLangProvider` (extends `shared/i18n`) | tenant `app_language` | `AppLangProvider` (layout effect, pre-paint) |

`AppLangProvider` is the **sole** authority writing `<html dir/lang>` on authed surfaces and the single
owner of `setAppLanguage()` (so the first authed paint already formats Jalali dates and applies RTL with
no flash). On sign-up the chosen language is persisted as the tenant's `app_language`; changing it in
settings propagates live. `toLang()` normalizes deterministically: `fa`/`fa-*` → fa; everything else
(including future `ar`, null, garbage) → en.

## What is bilingual today

- **Authenticated aesthetics app — fully fa/en + RTL.** Capture/report flow, memory/patients/timeline,
  settings/team/plan, Doctor Q&A, share sheet chrome, and all toasts/dialogs/offline-sync copy. RTL uses
  logical CSS properties (`*-inline-start/end`, `text-align:start`) and mirrors directional glyphs.
- **Public surfaces** — bilingual via the public seam.
- Numeric `t()` interpolation values render Persian digits under fa; Latin tokens (`Engram`, `Pro`,
  `Basic`, `MVP v2`), names, IDs, dates, and doses are never digit-converted.

## Deferred (known, not silent)

These follow a **different** axis or are a separate vertical — translating them via app-`t()` now would be
wrong or premature. Each needs its own future pass:

1. **`features/therapy/**`** — therapy is a not-yet-shipped vertical; a fa therapy tenant still sees
   English therapy chrome until the therapy i18n pass.
2. **`features/patient-surface/**`** — patient-facing share/Q&A pages follow `shareLanguage`/
   `reportLanguage` (the patient's language), not the app UI language. This is a content-axis concern.
3. **Login error `"Invalid email or password."`** — renders pre-auth on the public login screen; belongs
   to the public-seam pass, not the authed epic.

## Conventions for new work

- All new **authenticated** UI is bilingual + RTL-correct from the start (CLAUDE.md §5). Route chrome
  through `t()`; reuse the canonical glossary terms (visit/session/capture/report/patient/treatment/
  dose/aftercare/…) rather than coining per-screen synonyms.
- The guard catches JSX **text** leaks, not TS string literals (toasts, label helpers) — translate those
  by hand and, if you must leave one, tag `// i18n: <reason>` so it stays greppable.
- Verify under both languages before claiming done.
